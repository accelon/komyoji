# komyoji.adb 的定位：跟 cs.adb 一樣的 塊.段

> 作者 2026-11-02：komyoji 的頁 id「不必和網站一樣，要和 `D:\2026\sz` 的 `cs.adb` 一樣」。
> 這一頁記怎麼對、對到什麼程度、怎麼重跑。

## 1. 目標

`cs.adb`（VRI／CST4，sz）用三層地址：

```text
塊.段        d1.28          塊＝CST chunk、段＝CST pn
塊.段:句     d1.28:2        句＝該段內第幾行
```

komyoji 照抄這一套：同一個 `d1`、同一個 `28`，兩個庫指同一段巴利文，
跨庫跳轉不必再換算。`書` 也沿用 cs 的 id（`dn1`、`mn2`、`an10`…）。

## 2. 怎麼對（`src/align-cs.mjs`）

1. 兩邊都只留字母數字、轉小寫；kmj 句子先去掉段號前綴（`28.`、`102-109.`）與
   校勘方括號 `[…]`。
2. 把 cs 每本書的正文連成一大串（每列＝adb 一行＝一句），記住每列的起點。
3. 一章（＝一個經）先用整章中段 200 字當探針，在候選書裡定位，避免重複句亂跳；
   再從那個位置往後逐句 `indexOf`。
4. 位置回推是哪一列 → 那一列的 `塊`／`段`。

候選書按部類給（`dn*`→dn1–3、`mn*`→mn1–3、`sn*`→sn1–5、`an`→an1–11、`kn`→小部各書），
章不一定照分冊落在同一冊，所以是「同部類全部候選、用探針決定」。

「Dutiyaṃ.」這類小結、以及少數版本差異——這些在 cs 裡本來就沒有對應列。

## 4. 產出的 adb

```text
D:\accelon3\komyoji.adb    33 書、156,115 行、3.29 MiB
容器 source / tags / tables / attributes（沒有 tokens，和 cs.adb 一樣不建全文索引）
```

- 正文：`<區>`→`<書>`→`<塊>`→`<段 n>`，每行＝一句日譯。
- **目錄樹**：`00.xml` 宣告 `<隱><樹 s="*" t="區,書,塊">目錄</樹></隱>`，
  打出來的樹是 **5 區 → 33 書 → 381 塊**（和 cs 的 9 區／238 書／2976 塊同一個形狀）。
  兩個坑：`<區>` 只能在每部類的第一本書宣告一次（每本都宣告會出現「長部、長部、長部」），
  `<塊>` 不能帶 `t="段."`（否則段會變成目錄的第四層）。
- 133,642 句有日譯且有對上；4,620 句沒日譯，暫時不進正文。
- 段內的行數就是「句」；和 cs 的句數可能不同（我們的句子切得比較細），
  跨庫只用 `塊.段`，`:句` 只在同一庫內有意義（見 sz `docs/addressing.md`）。

解析驗證（`bun run out/addr-check.mjs`、`bun run src/toc-check.ts`）：

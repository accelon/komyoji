# 文法資訊的兩層：人工 in-context 與計算推定

> 作者 2026-11-03 的規劃：讀《四部尼柯耶》（九成以上的使用情境）用人工標注；
> 其他經文用這份資料推算，**但必須告訴使用者是電腦算的，不是人做的**。
> 這一頁定兩層的界線、標示方式與工具。

## 1. 兩層是什麼

| 層 | 來源 | 什麼時候有 | 標示 |
|---|---|---|---|
| **人工 in-context** | 光明寺表格（作者逐句標的） | 四部尼柯耶 6,080／6,554 段（**92.8%**） | `source=human` |
| **計算推定** | 用人工資料的「詞形 → 分析」分佈推算 | 其餘全部（含注疏、律、論、小部未收） | `source=推定` |

逐書覆蓋率：`node src/coverage-report.mjs`（dn1 92.8%、mn3 98.7%、sn3 100%、an11 66.7%…）。

**界線是「段」**：同一段裡只要有人在工資料，整段算人工；沒有的段落才走推定。

## 2. 推定的規則（保守優先）

1. 詞形（`form_clean`）在人工資料裡出現過 → 取出現最多的那一組分析，
   信心值＝該組佔比；佔比 < 0.6 標「分析不唯一」。
2. 詞形沒出現過 → 不猜，`conf=0.00`、`node=詞形未見於人工資料`。
3. 推定**只看詞形**，不看上下文（人工那層才有上下文）。
   同形多義（例如格位）在推定層會偏「最常見用法」，這是已知限制。

## 3. 一定要標示（這是作者的要求，不是建議）

- 任何顯示推定結果的地方（閱讀器、匯出檔、API）都要寫明
  **「計算推定，非人工標注」**，而且要和人工結果**視覺上分得開**。
- 混合輸出（一句裡有人工、有推定）要逐詞標，不能整段只標一次。
- 檔案輸出：`source` 欄（`human`／`推定`）＋ `conf`，結尾再附一行總數提醒。

## 4. 工具

```powershell
node src/infer-grammar.mjs --addr d1.28          # 人工覆蓋的段 → source=human
node src/infer-grammar.mjs --addr vs1.1          # 清淨道論（未收錄）→ source=推定
node src/infer-grammar.mjs --text "rūpaṃ aniccaṃ"
node src/infer-grammar.mjs --file sentences.txt
node src/coverage-report.mjs                     # 逐書覆蓋率
```

輸出欄位：`idx / word / root / pos / stem / gender / number / case / person / voice /
meaning / source / conf / node`。

實測（vs1.1，清淨道論）：174 個詞全部 `source=推定`，其中常用詞信心 0.8–1.0、
專名與複合詞落在「詞形未見」——結尾會印「※ 本輸出含 174 個計算推定值，不是人工標注」。

## 5. 之後要接的（閱讀器，回母區做）

- 讀者點一句時，先查這一段在不在人工覆蓋表（`coverage.tsv`／`src/coverage-report.mjs` 的結果）：
  - 在 → 顯示人工逐詞表（`blocks`），標「光明寺標注」。
  - 不在 → 顯示推定表，標「計算推定」並附信心值。
- 容器形式參考 `glossary`：`塊.段:句 → 詞表`，不擠正文。

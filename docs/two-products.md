# 這份日譯的兩個產出

> 作者 2026-11-03 的定位。這一頁不是規格，是「為什麼這樣做」——以後改動前先讀，
> 不要把第二個產出當成第一個的附屬品。

## 產出一：日譯巴利平行文本（對齊 cs）

- 內容：光明寺的日譯，一句一行，地址用 cs 的 `塊.段`（`d1.28`）。
- 現在的樣子：`D:\accelon3\komyoji.adb`，33 書、156,089 行；正文只有日譯，
  巴利原文在 `cs.adb` 的同一個 `塊.段`，靠地址對齊（跨庫跳）。
- 這是「平行文本」的骨架：同一個地址，一邊巴利、一邊日譯。

## 產出二：逐詞拆解與 in-context 文法

- 內容：每個被標注的詞——語形、語根、品詞、語基／活用、性／数／格、
  人称／態、意味——**跟著它所在的那一句**。
- 現在的樣子：`out/grammar/units.ndjson.gz`（172,355 行、17 MB）是完整原樣；
  `tokens.tsv.gz`（765,155 列）是攤平給 sz 的版本；副本在 `D:\2026\sz\data\kmj-grammar`。
- 也放上 GitHub release（和原始 html 同一個 release，不必跑工具鏈就能下載）：
  <https://github.com/accelon/komyoji/releases/download/html-2026-11-02/units.ndjson.gz>

## 為什麼第二個產出比詞典珍貴

1. **它是翻譯過程的中間紀錄**。作者是查字典抄的，但抄的時候一定做了判斷與校正——
   否則日譯不會通。所以每一列都帶著「這個詞在這一句為什麼這樣解」，
   那是靜態詞典沒有的資訊。
2. **同一個詞形在不同句子可以有不同分析**。詞典只給一個詞條；
   這裡給的是這一節經文裡的這一個用法（`na` 有時是否定、有時是別的）。
3. **它是唯一一份公開的「巴利三藏翻譯中間步驟」**。不齊全（重複段落不再標、
   早期幾冊品質差一些），但別處沒有。

## 所以設計上要守住的三件事

1. **原樣保存**：`units.ndjson.gz` 的 `blocks[].rows` 一字不改（含 `‐`、空白、貼錯欄的值）；
   清理與推論只發生在下游（`tokens.tsv.gz` 有 `flags`）。
2. **可獨立使用**：不綁 adb、不綁閱讀器。任何工具拿到 NDJSON 就能重建
   「哪一句、哪個詞、什麼語法」。
3. **可追溯**：每個單元有 `id`（`分冊/章/序號`），加上 `align.tsv` 就有 cs 地址；
   要回原始表格，解 release 上的 `komyoji-html.7z`。

- 把 `units.ndjson.gz` 當成對外釋出的資料集（不只是建置中間檔）。
- 四部以外的經文走「計算推定」，**必須標示非人工**：界線、規則與工具見
  [`grammar-inference.md`](grammar-inference.md)。
